# 本地视觉模型接入与安全边界

## 结论

当前 Mac Studio（M1 Max、32 GB 统一内存）使用 Qwen3-VL 2B Instruct 的 4-bit
视觉语言模型 `mlx-community/Qwen3-VL-2B-Instruct-4bit`，通过 MLX-VLM 在 Apple
Silicon 上本地推理。模型仓库约 1.78 GB；游戏实屏延迟以本机验收结果为准。
当前非游戏基准图结构化分类约 3.2 秒，相比原 4B 的约 5.2 秒缩短约 38%。

## 推荐职责

模型主要作为受限 `VisionAdvisor`：

- 把当前截图归类为已知页面、未知弹窗、加载中、游戏 HUD 或错误页；
- 为 OCR 结果补充上下文，例如判断同名文字属于按钮还是公告内容；
- 在寻路或活动界面改版后提供恢复建议。

只有允许列表中的固定动作可以在单帧置信度达到 0.95 时执行。模型不输出
任意坐标，也不决定以下动作：

- 提交科技；
- 踢出队员或营地成员；
- 最终指纹确认；
- 发送聊天消息；
- 关闭游戏或 MuMu 容器。

## 执行门槛

1. 截图先由现有 OCR 和页面规则判断；只有无法归类时才调用模型。
2. 输入为当前瞬时截图、OCR 文本、允许动作枚举和期望页面，不发送历史凭据。
3. 输出必须符合固定 JSON Schema：`state`、`action`、`confidence`、`evidence`。
4. 模型结论默认只写诊断日志；只有允许列表中的操作，才能在置信度达到 0.95 时
   授予执行权限。
5. OCR 或页面签名没有明确匹配时停止后续坐标流程，不连续猜测。
6. 涉及破坏性操作时，最终操作仍走现有精确姓名、固定流程
   和后台确认标记。
7. 推理服务仅监听 `127.0.0.1`，不得暴露到 Cloudflare Tunnel 或公网。

## 当前实装

- 模型：`mlx-community/Qwen3-VL-2B-Instruct-4bit`；
- 运行方式：`transport: "http"`，仅监听 `127.0.0.1:8092`；
- 生命周期：任务开始按需启动并预载模型，任务结束停止服务释放统一内存；
- 性能：常规画面先走 fast OCR；未命中已知页面时每 5 秒使用一次 accurate OCR，
  模型按单请求后台运行且不阻塞主操作循环，单次输出限制为 64 tokens；
- 模式：`guarded`；模型只返回页面分类和证据，归一化后的模型动作仍永远为 `wait`，
  由本地允许列表把极高置信度状态映射到固定动作；
- 已开放动作：固定登录按钮、登录后宣传页底部关闭区、HUD/地图状态确认；科技、
  聊天、寻路与踢队员流程可使用 AI 判断，但最终仍映射到配置中的已校准动作；
- 禁止动作：踢出营地成员、最终指纹确认和任何未经配置校准的模型生成坐标；
- 截图：每次模型调用使用独立瞬时截图，响应或异常后立即删除；
- 故障降级：模型未安装、启动失败、超时或 JSON 不合规时，任务继续走 OCR 与既有
  确定性规则。
- 沙盘页面文字不能由模型直接放行；只接受限定小区域的真实中文 accurate OCR。
- 贡献页采用混合读取：Vision OCR 负责全部数值与溢出数字按列拆分，模型只按可见
  行号补姓名。108 名成员实机完整读取约 73 秒，不对相似姓名做模糊合并。

控制入口为 `scripts/manage-local-agent.sh`；单独管理模型可执行
`scripts/local-model.sh`。所有模型运行文件位于 `.local-model/` 并已排除出 Git。

## 后续扩展顺序

1. 离线收集并脱敏一批正常 HUD、宣传页、语音邀请、队伍页、地图页和故障页截图。
2. 选择新的本地视觉模型后先以 `shadow` 模式做只记录、不点击的基准比较。
3. 登录、地图和 HUD 阶段补齐确定性页面签名；模型不得成为执行授权条件。
4. 科技、寻路和踢人保持确定性实现。
